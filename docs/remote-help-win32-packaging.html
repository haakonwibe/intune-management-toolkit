The installed binary reports a different version from the installer

Checked on a reference machine: C:\Program Files\Remote Help\RemoteHelp.exe reports FileVersion 10.4.10008.1000, while remotehelpinstaller.exe carries 5.2.1040.0. Different schemes entirely — not two points on one line.

The detection rule below uses 10.4.10008.1000, the installed value, which is the one Intune compares against. Had it been set from the installer's version, every device would report a failed install while running the app perfectly well. Re-check this after any future Remote Help refresh with:

(Get-Item "$env:ProgramFiles\Remote Help\RemoteHelp.exe").VersionInfo

Before unattended sessions will work

outside the scope of these packages
  • Intune Management Extension must be present on the target device — it orchestrates the unattended session.
  • Remote Desktop must be enabled on the device. A Settings Catalog configuration profile is the usual way in.
  • Helpers need the permission Remote Help app — Windows unattended control remote sign-in, scoped to the target devices.
  • The device must be awake and online. Asleep, hibernating, or shut-down devices can't take an unattended session.
  • The agent self-updates once installed, and that process can't be controlled or paused. Expect the deployed version to drift upward from 1.0.15008.300 — which is why detection is by product code, not version.

Packages and sidecar _Metadata.json files are in local-packages\IntunePackages\; source installers in local-packages\Installers\. Both are gitignored. Rebuild any package with scripts\apps\intunewin-builder\New-IntuneAppPackageFromInstaller.ps1.

Icons for all three apps are in local-packages\Logo\, named to match each app so the builder resolves them automatically. Remote Help.png is the 256×256 mark extracted from the installer's own icon resource; the two Azure Virtual Desktop components reuse it, since neither MSI carries any icon artwork of its own.
